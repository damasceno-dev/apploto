# Implantação da filial — Design 4.9.15 candidate

Independent semantic review remains pending against canonical v68. The product/catalog are reconciled; accepted design sync markers remain v67 until that review. No native or actual customer activation is implied.

## Go-live

**Entry and purpose.** The current Manager/Admin enters Gestão → Cadastros → Implantação da filial. The existing branch shell verifies authority before mounting private reads. Its return goes to Manager Work Queue, preserving branch and mode. Source contents stay out of URLs and logs.

**Regions.** A short checklist explains the two ways to start. Collapsed setup creates only proved missing catalog destinations and holidays through existing commands, and offers a separate explicit operator/account grant with readable current permissions. Cashbox and Tab grants remain separate; neither pairing nor import assigns them. Physical count reuses OpeningCount, with a separate explicit-zero confirmation. Manual obligations show account/client/operator/type, source evidence and dates; cheque installments remain separate items. Existing manual-origin obligation history offers versioned substitution/cancellation with reason, subject to backend consumption/lock checks. Imported obligations preserve the activated cutover evidence: the server-owned nullable SourceImportId identifies their origin, the history shows an explanatory message and disables manual revision, and direct manual amendment/cancellation returns the backend ownership refusal even before consumption; subsequent fiado/cheque events remain supported. Opening type choices require the client/CAIXA money classification with no monthly role; later type reclassification cannot turn the asset into own income/expense. The import region contains an export guide, explicit profile/encoding/files (a repeated source cannot silently change interpretation), resumable imports, mapping editor, preview and exact confirmation/result. Each region uses Card/FormField/NativeSelect/Input/DateField/TimeField/MoneyInput/Textarea/Notice/Button; it introduces no new component system.

**Mapping and comparison.** Source rows expand into a definition list of original columns and an explicit action. Readable current target selectors cover catalog references, custody, terminal/product, payroll category, close field and attendance status. Source precision stays visible; the chosen target amount/hours, reason, date/year and completeness are editable decisions. M9.5 suggestions state provenance and require deliberate use. ID/date range exclusions show exact counts and expand to individual source identities. Unknown-history quarantine remains blocking. Preview separates blockers from explained exceptions/exclusions, exposes original versus reviewed plans and preserves unavailable opening/association/method evidence. All amounts/comparisons come from the server. Attendance preview shows raw legacy totals beside recalculated total/balance and the exact effective policy, using the same calendar, segment and calculation rules as current attendance writes.

**Confirmation and recovery.** The manager inspects exact source digest, schema/tool/mapping/preview versions, target fingerprint and plans before checking the confirmation. No confirmation is restored after reload or edits. Frozen command identity survives an uncertain response; verify/retry keeps the same payload/key within the existing replay window. Deliberate discard requires checking server state. Unsent drafts are identity/branch/resource scoped and restored explicitly after authority is checked; a mapping draft from another revision is warned for reconciliation. Original CSV/password bytes stay only in memory until upload, never in device recovery storage; selecting the same files re-enables verification after reload. Activated imports remain read-only, with source→target evidence and resume. Backend errors render verbatim.

**Layout/accessibility.** One column at compact/375px; source rows paginate 20 at a time and collapse details, avoiding a wide spreadsheet. At larger widths each row's source fields may use two columns while control order stays unchanged. Long references wrap; technical evidence is behind details and never a mandatory GUID input. Use semantic surface/border/text/action/feedback tokens and inherited type/spacing tokens, both themes, existing touch/control sizes and visible focus. Native details/labels and named controls preserve keyboard order. Enlarged text reflows without a horizontal page scroll. Loading/errors announce through Notice; failed saves retain candidates. Only the current action can dispatch while another command is busy or unresolved.

**Verification boundary.** Real local browser/API tests cover upload→mapping→preview→activation, lost-response verification, result/reload, subsequent noncash payment Member deep-link refusal, and fresh manual setup/explicit grants/zero count/debt/first-start, compact width, enlarged text, dark theme and keyboard. Static token/contrast checks do not prove screen-reader speech. Independent review, Mobile/native execution, AA retained-retired-product lifecycle, customer source resolution and production activation remain separately pending.
