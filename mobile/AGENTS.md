# Mobile Agent Notes

Milestones for this area live in `mobile/docs/milestones.md`.

## Stack direction

- Use Expo
- Use Expo Router
- Use NativeWind
- Package name is `@loto/mobile`; ESM only; the tsconfig extends the root `tsconfig.base.json`
- Consume `@loto/api` and `@loto/core` as source packages compiled by Metro — no build step in `shared/`

## Integration guidance

- Reuse `shared/api` for the same API contract, raw functions, and TanStack Query helpers used by the web app; screens use the hooks from `@loto/api/queries`
- Consume `shared/core` (day-one) for BRL/CPF/date formatters and pt-BR enum-label maps shared with web
- Mobile calls the backend directly — there is no BFF. Tokens live in the platform secure store and reach `@loto/api` through the client's token-provider interface
- Keep upload, media, and device-specific adaptation at the mobile app boundary
- Consume design guidance from `design` tokens, specs, assets, and references
- Business day and time come from `GET /branch/current`, never the device clock
- Errors render `ResponseErrorJson.ErrorMessages` verbatim through the shared `ApiError` normalization

## Design tokens

- Read `design/tokens/*.json` at build time through the NativeWind theme — tokens never pass through `shared/`
- App code uses semantic and domain tokens only: no raw hex/rgb literals and no primitive-token references outside the token-adapter module (enforced by lint)
- Light and dark themes ship together

## UI guidance

- Keep mobile UI components inside `mobile`
- Do not create a shared runtime `ui-mobile` package yet
- Do not force web-oriented components into React Native
- Build mobile components using the same design tokens and component contract (`design/specs/components/`), but let mobile own its implementation
- Mobile clones web: the screen set and its semantics are identical (`design/docs/screens.md`); interaction patterns are platform-appropriate, and dense screens adapt to small screens instead of being redesigned

### M1 typecheck, probe and raw-color decisions

- `typecheck` runs `expo customize tsconfig.json && tsc --noEmit`. This is Expo's [documented CI route-generation command](https://docs.expo.dev/router/reference/typed-routes/#type-generation), not an internal generator or a Metro server. It regenerates ignored `.expo/types/router.d.ts` and `expo-env.d.ts`; the precise app-local `.gitignore` entry prevents the CLI from creating/changing tracked ignore content. The multi-base tsconfig remains intact. A compile-only Href sentinel rejects missing generation; a nonexistent Link href was rejected with TS2322 in a fresh isolated install.
- The probe reads `expoSdk` from runtime Constants (null if missing), the installed Expo package version from bundled `expo/package.json` metadata, and default device Intl resolved options (including locale/timeZone). It has no manually maintained SDK/package fallback. Package metadata is not represented as an engine measurement. Actual Hermes readings are recorded in Mobile M1.
- Outside styles, only an entire trimmed hex/function string or template fails, including exported palettes. Style values and arbitrary classes retain substring checks; CSS at-rules including `@apply` are checked. Named colors stay context-dependent; duplicate diagnostics are suppressed. App-local rule semantics still match Web. Dependency keys are sorted; `supportsTablet` was removed so M1 does not decide tablet support ahead of M12.
- Reference-number and aria-label copy fixtures pass while isolated palettes are still rejected. Mixed composite values outside recognized style contexts are a known, non-blocking trade-off; broad style-key matching was not added.

## M2 session and data boundary (2026-10-27)

- `src/config/api.ts` alone reads `EXPO_PUBLIC_API_BASE_URL`; release requires HTTPS. Configuration failures are explicit. No platform environment/storage enters Shared.
- `src/session/engine.ts` owns one verified identity and at most one branch. `src/storage/native.ts` stores the versioned identity/refresh/branch envelope only in Expo SecureStore; AsyncStorage holds non-secret installation/sign-out markers and scoped input. A failed secure read/write/delete is visible, never a plaintext fallback. An installation marker prevents iOS keychain inheritance after reinstall; a sign-out tombstone prevents stale restoration after deletion failure.
- `src/session/provider.tsx` owns React/TanStack contexts per immutable scope. Old queries are cancelled/cleared; token wait, response headers and delayed bodies are fenced. Identity login alone cannot open a branch gate; current role/business time come from `/branch/current`. Branch changes clear active context/selections, retaining isolated device input for authorized return. Role/day/membership changes pause writes and clear the applicable active selections.
- Renewal is single-flight, persists the rotated pair before rebuilding branch authority, retries a GET once and never replays a write. Unknown rotation permits only one explicit verification. Logout waits for an in-flight rotation and revokes its new refresh token; local cleanup is distinct from confirmed server revocation. Foreground/NetInfo/timers request authoritative reads; they never advance business time or queue writes.
- `src/data/auth-policy.generated.ts` and retained-request schemas derive from the committed server OpenAPI via `pnpm --filter @loto/mobile generate:auth`; lint checks drift. Generated Shared files remain untouched. Request-schema checks protect retained input structure, not financial outcomes or permissions.
- `src/storage/scoped.ts` partitions by verified UserId + SHA-256 of the exact authenticated canonical Email + BranchId + resource and schema version. Passwords, tokens, secret URLs and durable version/ETag preconditions are rejected. Drafts retain original base/input/revision; a fresh resource/grant callback is required before restoration and an older acknowledgement cannot delete later edits. Storage failure retains a visible in-memory candidate. No TTL silently deletes unresolved input.
- `src/data/navigation.ts` holds validated app-relative destinations/origins only; fresh branch/grant checks run for each hop. Capability/authentication links stay outside ordinary durable intents. Navigation mode supplies no authority.
- `src/data/operations.ts` supports only the three currently contract-idempotent financial create APIs. Expo Crypto supplies v4 UUIDs; exact payload/key are persisted before dispatch. Restart converts pending to uncertain, same-intent verification keeps bytes/key, changed unresolved input is blocked, and a conservative server-time replay window requires reconciliation when expired/unknown. Mutation retries remain zero. `guarded.ts` uses current ETag/If-Match in memory and requires a fresh read after conflict/uncertainty; a deduplication header cannot make a guarded command idempotent.
- SDK-compatible native additions: SecureStore/Crypto 57.0.4, AsyncStorage 2.2.0 and NetInfo 12.0.1. Jest 29.7.0/jest-expo 57.0.6, RNTL 13.3.3 and renderer 19.2.3 test actual generated calls and provider boundaries. `tsconfig.test.json` checks tests separately. Existing pins and ignored build-script policy remain unchanged.
- `EXPO_PUBLIC_NATIVE_SESSION_PROOF=1` enables the DEV-only technical harness; fake credentials stay in memory until login and the password is cleared on submit. Financial fault injection also requires a loopback API. This is no product login/cashier feature; release disables the harness/fault path. Use only owned disposable fixtures, keep runner artifacts/credentials outside Git, select a simulator explicitly and run OS tests sequentially for the same user (M8 keeps one active refresh token per user).

- Verification: 24 tooling tests + 87 Jest/RNTL tests; full workspace checks and both dev/production source maps pass. Real native M8 login/branch/clock, durable input/held intent, uncertain transaction/restart/exact replay and current grants passed on both OSs against an owned disposable .NET/PostgreSQL stack. Supported API reads confirm one durable result per OS from two identical dispatches with matching ETags. Full verification evidence is recorded in Mobile M1/M2.
- `EXPO_PUBLIC_NATIVE_FIXTURE_PREFILL=1` adds a DEV-only loopback fake-data button; the fixture server returns input, never credentials issued by the API. Real native auth/crypto/storage/transport still run. `LOTO_NATIVE_APP_ID` permits a separate disposable proof build for fresh-install/reinstall checks; it does not change tracked app identifiers. Never uninstall/reset the normal app for automated proof. ## M3 design system (2026-10-27)

- Components live in `src/ui/` and are imported from `@/ui`; theme access is `useTheme()` from `@/theme/provider`. Style from tokens (`colors.sem.*`, `colors.dom.*`, `textStyle(role)`, `spacing`, `radius`, `shadowStyle`); NativeWind classes may use the token names (`bg-sem-surface-default`, `text-dom-cash-variance-shortage-fg`, `p-inset-panel`, `text-body`). Never write raw colors or primitive names; only the generated `src/theme/token-adapter.ts` holds values.
- After any change to `design/tokens/*.json`, run `pnpm --filter @loto/mobile generate:tokens`; `lint` fails on a stale adapter or an unknown `sem-`/`dom-` class.
- `ThemeProvider` sits outside the session providers and renders nothing until the stored preference is read. Theme preference is device presentation state (`loto.theme-preference.v1`); never clear it with the session and never store it in SecureStore.
- Pressables whose style depends on pressed state use `PressableBox` (NativeWind's JSX interop drops function styles on device). Disabled/busy handlers are guarded, not only omitted.
- Use `ScreenScroll` for scrolling screens: Android 15+ draws edge to edge and does not resize the window for the keyboard. Overlays pad for the keyboard on both platforms.
- Open pickers/menus inside a dialog through the normal components: they detect the surrounding overlay and render as in-modal layers. Do not nest a second native `Modal`.
- Every field-like control, composite ones included (DayStepper, MonthField), reads `disabled`/`readOnly` through `useFieldControl` so a FormField's state applies, and guards its callbacks with it. Text-backed controls rewrite their text only when the external value changes, never on a plain re-render.
- `moveFocusTo` sends accessibility focus only while a screen reader runs and gives native focus only to text fields (native focus on a heading pins Android scroll views).
- MoneyInput takes and emits entry digits (`''` blank, `'0'` recorded zero); the arithmetic parser is demonstrated only in the DEV gallery until Design 4.9.7.
- The DEV gallery is `src/probes/gallery/`, reached from the home route's `__DEV__` require; keep technical strings there so `tooling/check-bundles.mjs --production` keeps rejecting leaks.

## M4 entry and navigation shell

- `src/shell/policy.ts` owns the typed destination keys, role/mode visibility and catalog fallbacks; each destination has a concrete guarded Expo route. Keep `src/contract-checks/typed-routes.ts` and the route tooling gate aligned when adding a route. Mode/URL/storage never authorize API work.
- `src/shell/entry.tsx` uses the existing engine and generated branch query. Login/branch presentation controllers survive scope replacement in memory; passwords never persist and clear on submit or leaving the journey. Session commands remain engine-owned, not a second client/auth path.
- The engine reads generated self-context at creation/recreation, foreground, mode/shift entry and permission-refusal verification. Clock-only timer/focus refreshes do not re-read self-context. Verified identity/branch baselines survive read failures and scope recreation; quiet self-context checks hold branch writes internally until verification finishes without publishing checking or a verification rail item. Foreground/reconnect holds cover the complete profile/clock/self-context chain, including the final transport guard. Opening the account menu quietly refreshes authority so newly granted operator links become usable. `selfStatus: failed` is distinct from a missing operator or an empty account set. Explicit verification and failed authority reads pause writes. A changed role/link/grant cancels scoped work and clears active selections; no refused write is replayed.
- `useShell().navigate(path, keepOrigin)` records app-owned return context; shortcuts omit an origin. Navigation persistence contains only allowlisted non-secret addresses/mode/origins in a verified UserId + canonical-email hash + branch partition. Future features must supply fresh resource validation before restoring resource origins. Financial input and SecureStore stay separate.
- Explicit logout/branch switch cannot turn an outgoing protected screen into an anonymous/unscoped intent; actual incoming links reset capture through the native Linking event. Selecting Y rejects an X intent. Keep every return behind fresh session/branch/permission/resource checks.
- The compact drawer and account sheet use M3 overlays; a confirmation inside the menu is an in-modal layer, never a second native Modal. Field state is additive (including invalid); per-option segmented-control unavailability remains readable with its reason. The Stack uses native back/swipe and respects reduced motion.
- `tooling/native-shell-stack.mjs` uses Mobile-owned disposable supported-flow fixtures in `native-stack.mjs`, with no runtime Web-source import or rewriting; credentials/raw evidence remain outside Git. `native-shell-flow.mjs` writes native-touch journeys outside Git. Select each OS target explicitly, use owned Metro/API ports and stop only resources recorded by that run. Independent/physical/spoken acceptance is recorded in the milestone, not inferred from these tools.
